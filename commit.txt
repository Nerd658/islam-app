2026-08-04 — Quran offline audio (IndexedDB), full test suite, README rewrite

What changed:
- Replaced localStorage-based Quran offline storage with IndexedDB binary audio storage.
  Audio MP3 files are now fetched as Blob and stored natively; blob:// URLs are served
  for offline playback instead of unreachable remote URLs.
- Added per-surah download progress UI (shows "Téléchargement X/Y versets..." during
  download instead of a simple toggle button).
- playVerse() now checks IndexedDB (getOfflineAudioUrl) before falling back to the
  remote URL, making the player truly offline-capable once a surah is downloaded.
- Added verses.quran.com audio CDN to vite-plugin-pwa Workbox runtimeCaching with
  CacheFirst strategy (quran-audio-sw-cache, 500 entries, 90 days) as a secondary
  service worker layer.
- Created a complete Vitest/RTL test suite covering 10 test files and 34 test cases
  across all major pages and components.
- Rewrote README.md: professional tone (no emojis), accurate tech stack (React 19,
  Vite 6, etc.), documented IndexedDB offline system, all env vars, API integrations,
  security architecture, PWA, and contributing guidelines. Language: French.
- Enhanced setupTests.js with global mocks for Howler, AudioContext, geolocation,
  navigator.vibrate, matchMedia, URL.createObjectURL, and IndexedDB.

Why:
- The previous offline implementation only saved audio URLs to localStorage. When
  offline, those URLs are unreachable — the feature was non-functional. IndexedDB
  stores the actual MP3 binary data, enabling genuine offline playback.
- The test suite was minimal (1 trivial Header test). Expanding to 34 meaningful
  behavioral tests provides confidence in regressions and documents expected behavior.
- README was inaccurate (stated React 18 when 19 is used, omitted all new features,
  no description of the offline system or IndexedDB architecture).

Breaking changes:
- None. The offline storage is additive. Users who had previously "downloaded"
  surahs via the old localStorage mechanism will lose that cached data (it will
  not be migrated to IndexedDB), but they can simply re-download.

Notes for review:
- IndexedDB storage for a full surah (audio Blobs) can range from 10-50MB.
  Ensure users are informed via the progress UI before downloading.
- Blob URLs created from IndexedDB are revoked on chapter change/unmount via
  useEffect cleanup in useQuranOffline — no memory leak.
- The Workbox service worker (SW) acts as a secondary audio cache layer for
  URLs that were already fetched but not explicitly downloaded via the IndexedDB
  flow (e.g., verses streamed during online playback will be SW-cached for replay).
- Test for PrayerTimesList countdown (fake timers + setInterval) uses
  vi.advanceTimersByTime(1100) inside act(). The exact countdown string is not
  asserted to avoid brittleness with fake timer synchronization.
