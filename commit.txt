[2026-08-01] — Refactor: Externalize public API URLs to environment variables (v2.1.2)

What changed:
- Removed all hardcoded URLs for external APIs (Aladhan, OpenRouter, Nominatim OpenStreetMap, and Quran.com) from the Frontend source files (`Home.jsx`, `Chat.jsx`, `fetchEvents.js`, `fetchPrayerTimes.js`, `useLocationSearch.js`, `QuranReader.jsx`).
- Removed hardcoded URLs from the Backend controllers (`prayerController.js`, `chatController.js`).
- Created a comprehensive `.env` (and `.env.example`) setup for both the FRONTEND and BACKEND environments to manage all URLs centrally.

Why:
- Even for public APIs without API keys, hardcoding URLs is a bad practice. It reduces maintainability, makes testing difficult (hard to mock), and forces a code change + full rebuild if an endpoint changes. Using environment variables allows dynamic configuration per environment.

Files affected:
- FRONTEND/islam app/.env (New)
- FRONTEND/islam app/.env.example (New)
- FRONTEND/islam app/src/api/fetchEvents.js
- FRONTEND/islam app/src/api/fetchPrayerTimes.js
- FRONTEND/islam app/src/hooks/useLocationSearch.js
- FRONTEND/islam app/src/pages/Home.jsx
- FRONTEND/islam app/src/pages/Chat.jsx
- FRONTEND/islam app/src/components/QuranReader.jsx
- BACKEND/.env.example
- BACKEND/controllers/prayerController.js
- BACKEND/controllers/chatController.js

Breaking changes:
- None. However, developers must now copy `.env.example` to `.env` in both FRONTEND and BACKEND to successfully run the application locally.
