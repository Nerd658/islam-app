[2026-08-01] — Security Audit & Hardening (v2.0.1)

What changed:
- **Backend**: Resolved all `npm audit` vulnerabilities. Zero vulnerabilities remaining in production dependencies.
- **Backend**: Added `hpp` (HTTP Parameter Pollution) middleware to protect against array-based query parameter attacks.
- **Backend**: Configured a strict Global Rate Limiter in `app.js` (100 requests / 10 minutes per IP) to protect the entire API surface from DDoS attacks and scraping, supplementing the strict Chatbot rate limiter.
- **Backend**: Configured `express.json({ limit: '10kb' })` to prevent large payload attacks.
- **Backend**: Hardened `cors` to expect a restricted `FRONTEND_URL` in production (defaults to `*` for local dev).
- **Frontend**: Updated multiple dependencies and ran `npm audit fix --force` to patch deeply nested vulnerabilities (e.g., `glob`, `tar`, `postcss`). Upgraded `react-router-dom` to latest. The remaining audit warnings on `react-router` strictly apply to Server-Side Rendering (SSR) / React Server Components (RSC), which are not used in our Client-Side React SPA.

Why:
- A rigorous security audit was requested (`/goal audit secu`).
- Protecting the backend from DDoS, parameter pollution, and excessive payload sizes is critical for stability.
- Dependency vulnerabilities (even deep transitives) must be patched regularly.

Files affected:
- BACKEND/app.js — Added new security middlewares.
- BACKEND/package.json & package-lock.json — Updated dependencies.
- FRONTEND/islam app/package.json & package-lock.json — Updated dependencies.

Breaking changes:
- None.

Notes for review:
- Before deploying to production, make sure to set the `FRONTEND_URL` environment variable in your `.env` so that CORS correctly blocks unknown origins.
